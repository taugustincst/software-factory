**Stack:** React 19 + Vite (client), Fastify + Zod (API), Postgres 16 with Drizzle ORM and committed migrations, self-hosted session auth (argon2id), TypeScript strict throughout, Vitest projects for web (jsdom + Testing Library) and server, coverage gates, single Docker image serving both.

## Quick start

```bash
npm install
cp .env.example .env
npm run db:up          # Postgres 16 via Docker Compose
npm run db:migrate     # apply the committed migrations in drizzle/
npm run dev            # web http://localhost:5173  (proxies /api → :3000)
```

## Commands

| Task | Command |
|---|---|
| Dev (API + web, hot reload) | `npm run dev` |
| Lint + format check | `npm run lint` |
| Type check | `npm run typecheck` |
| Tests + coverage | `npm test` |
| Production build | `npm run build && npm start` |
| Start local Postgres | `npm run db:up` |
| Apply DB migrations | `npm run db:migrate` |
| Generate a migration after changing `server/db/schema.ts` | `npm run db:generate` |
| Container | `docker build -t {{factory.name}} .` |

Server tests run against a real Postgres — CI provides an ephemeral one as a service container and runs `npm run db:migrate` before the suite; locally they use `DATABASE_URL` (default: the Compose database).

## Layout

```
web/                 Vite root: index.html, src/ (React app, API client, tests)
server/              Fastify API: config, app factory, auth, routes, tests
server/db/           Drizzle schema, client factory, migration runner
drizzle/             committed SQL migrations (generated by drizzle-kit)
docker-compose.yml   local Postgres 16 for development
dist/client, dist/server   build output; the server serves the client in production
docs/specs/          specs, plans and reviews per change
```

## Auth

Self-hosted session auth: `server/auth.ts` + `server/routes/auth.ts` (rate-limited credential endpoints, 10 attempts / 15 min / IP; argon2id password hashes via @node-rs/argon2; the cookie carries a random token, the database stores only an HMAC of it keyed by `SESSION_SECRET`). `POST /api/auth/register|login|logout`, protected example `GET /api/me`, RBAC example `GET /api/admin` (`requireRole('admin')` chained after `requireAuth`). The React app ships a login/register form and renders a protected account panel only when `/api/me` accepts the session. Registration always creates role `user`; promote in the database to make an admin. Set a real `SESSION_SECRET` in production — the server refuses to start in production with the dev default.
